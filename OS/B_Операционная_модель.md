# B. Операционная модель агентства «Мегаполис»

> Часть операционной системы (ОС) «Мегаполис», версия 1.0 от 26.09.2026. Главный вход в ОС — дашборд (`07_Дашборд.html`), оглавление — `OS/00_Оглавление.md`.
> **Принцип:** модель описывает, *как бизнес должен работать*. Колонка «Сейчас» отдельно показывает, *что есть на деле*. Если документ или агент существует, это ещё не значит, что функция закрыта.
> Единые значения (порог клиента, бюджет, SLA и т. д.) берутся **только** из раздела 0. Если в другом документе цифра другая, верна цифра отсюда, а расхождение фиксируется в `L_Проверка_согласованности.md`.

**Позиция на рынке (гипотеза для проверки, см. C):** небольшое экспертное агентство, где покупателя ведёт один опытный брокер с сильной аналитической поддержкой ИИ. Обещание клиенту: *честный подбор новостройки по цене застройщика, с проверкой фактов, без наценки для покупателя*. Отличие от крупных сетей: личный эксперт и прозрачная проверка. Отличие от частных риелторов: системная аналитика и документальная проверка каждого утверждения.

**Отказы на 12 месяцев (решение ОС, подтверждение J-07):** направление «Китай» (пауза до отдельного решения); SaaS; вторичный рынок как самостоятельный продукт (только как часть сделки обмена через партнёра, см. направление 2); аренда; клуб о Москве до первой сделки (кроме бесплатной подготовки концепции).

| Поле | Содержание |
|---|---|
| Результат | Клиент понимает, что получает, платит ли он (при покупке новостройки — нет, платит застройщик), и проходит путь без провалов в сервисе. Это даёт рекомендации и повторные обращения |

| Выход | Описание продуктов → Маркетинг (офферы) и Продажи (предложение о работе) |
| Отвечает | М |
| Делает сейчас | М; тексты — CMO |
| Переход | Остаётся за М; при найме Брокера-2 — обязательное обучение по этому документу |
| Где хранится | Этот раздел + `OS/G_Клиентский_путь_и_воронка.md` |
| Метрика | Доля клиентов, дошедших от диагностики до подбора; оценка сервиса после сделки (1–10); число рекомендаций |
| Влияние на деньги | Сервис определяет конверсию «диагностика → сделка» и будущие рекомендации, а это самый дешёвый канал |
| Сейчас | ❌ Продуктовой линейки и стандартов сервиса в документах нет. В плейбуке CMO есть смысловые элементы |

**Продуктовая линейка:**

| Продукт | Для кого | Результат для клиента | Кто платит | Статус |
|---|---|---|---|---|
| П1. Подбор и покупка новостройки «под ключ» | Покупатель от 20 млн ₽ (жить или вложить) | Шорт-лист 3–5 проверенных вариантов, показы, переговоры об условиях, сопровождение до регистрации ДДУ и выплаты | Застройщик (комиссия агентства через агрегатор) | **Запуск сейчас** |
| П2. Консультация «проверка новостройки» | Покупатель, который уже выбрал ЖК | Проверка застройщика, документов, цены и условий, риски письменно | Бесплатно как вход в П1 | Сейчас, как лид-магнит |
| П3. Обмен: продать свою квартиру → купить новостройку | Собственник, который хочет переехать в новостройку | Продажа вторички (через партнёра-агентство или трейд-ин застройщика) + П1 | Покупка — застройщик; продажа — по договору с партнёром (решение J-08) | Позже: при первом таком запросе |
| П4. Продажа квартиры собственника | Собственник | Продажа вторички | Собственник | Не сейчас: другая экспертиза и экономика, открывается по решению после 3 сделок П1 |
| П5. Аналитика рынка для собственника | Собственник в ЖК, где есть спрос | Отчёт по ценам и спросу в его ЖК | Бесплатно (лид-магнит для П3 и П4) | Позже |

**Стандарты сервиса (обязательные):**
1. Первый ответ в пределах SLA (раздел 0).
2. Каждая характеристика объекта в материалах клиенту имеет источник: сайт застройщика, проектная декларация на наш.дом.рф или прайс TrendAgent с датой. Без источника пишем «не подтверждено».
3. Цена в любом материале — с датой и источником, перед отправкой перепроверяется, если старше 3 дней.
4. После каждого контакта у клиента есть понятный следующий шаг и дата.
5. Клиента фиксируем у застройщика через агрегатор **до** первого показа или запроса по конкретному ЖК (иначе комиссия может быть потеряна).
6. Персональные данные клиента хранятся только в CRM, не в чатах агентов и не в публичных материалах.

## Связи между направлениями (главные потоки)

1. **Маркетинговый поток:** контент или объявление (3, 4) → обращение → CRM (10) → первый ответ (6) → диагностика → бриф → подбор (7) → КП → показы → сделка → выплата (9) → рекомендация → снова маркетинг (3).
2. **Объектный поток:** лот застройщика группы 1 → проверка фактов (7) → упаковка (Рынок) → Юрист → публикация на Авито (4) → лид → Продажи (6) → показ → сделка.
3. **Денежный поток:** решение о тесте канала (1) → лимит и стоп (9) → запуск (4) → лиды и их стоимость (10) → решение на еженедельном обзоре (1).
4. **Поток найма:** метрика нагрузки (10) → триггер (8) → роль закрыта → передача функции по матрице H.
5. **AI-поток:** повторяемая ручная задача замечена (10) → доказательство повторяемости (3 раза за 30 дней) → ТЗ → Инженер → приёмка → функция частично автоматизирована (11).
